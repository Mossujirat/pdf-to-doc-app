# Convert on our server, not in the browser

Users' files are often confidential, so converting entirely in the browser looked like the natural choice. We tested it and decided against it. On a real Thai contract, pdf.js put spaces inside Thai words (about 4 per text page) and found no tables, and the OCR that runs in a browser (tesseract.js) had the lowest Thai accuracy of any engine in published benchmarks. So conversion runs on our own server. The source file is processed in memory and deleted as soon as conversion ends. The outputs are kept for 10 minutes after that, or until the user deletes them sooner. (Until 2026-10-21 the output was deleted on its first download; that was dropped so that a failed download can be retried and both formats fetched.) File content is never logged and never sent to a third-party AI service. To enforce this, and to contain any parser exploit in a publicly uploaded PDF, the converter runs in a Docker container with no network access and only in-memory scratch space (ADR 0004 says how).
